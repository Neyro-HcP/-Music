# Совместная работа ChatGPT и Claude над НсП Visual Lab

## Что даёт бесплатная схема

Оба помощника могут опираться на один и тот же репозиторий GitHub. Это не означает, что они автоматически видят переписку друг друга или запускают друг друга.

- Claude можно подключить к репозиторию через GitHub-интеграцию в чате или проекте и синхронизировать выбранные файлы.
- В бесплатном чате Claude используй GitHub прежде всего как источник контекста и для ревью. Для агентной работы, которая сама редактирует файлы и запускает команды в репозитории, нужен Claude Code с подходящим платным планом либо доступ через API.
- Автоматическая передача задач между двумя моделями требует отдельного оркестратора и интеграций. API-вызовы оплачиваются отдельно по использованию; бесплатный доступ к чату не означает бесплатный API.

## Безопасный порядок работы без API

1. Подключи к Claude репозиторий `Neyro-HcP/-Music`. Для начала выбери `README.md`, `CLAUDE.md` и только файлы, относящиеся к конкретной задаче.
2. Перед ревью нажми Sync в Claude, чтобы он читал актуальную версию выбранных файлов.
3. Поручи одному помощнику вносить изменения. Второй помощник должен независимо проверять план, diff, ошибки и пограничные случаи.
4. Передай Claude описание задачи и diff или список изменённых файлов. Попроси конкретные замечания с путями файлов и строками, а не общую оценку.
5. Передай замечания Claude в ChatGPT. Решения по замечаниям принимай после проверки кода; не применяй предложения автоматически.
6. После принятых изменений снова синхронизируй репозиторий в Claude и попроси проверить итоговый diff.
7. Не редактируй одни и те же файлы одновременно в двух местах. Эксперименты делай в отдельных ветках, изменения объединяй через Pull Request.

## Готовый запрос для Claude

Скопируй этот текст в чат Claude после подключения репозитория:

> Изучи README.md и CLAUDE.md репозитория НсП Visual Lab. Выступай как независимый технический ревьюер и второй разработчик. Не выдумывай структуру проекта: сначала изучи реальные файлы. Для каждой задачи анализируй затронутые файлы, возможные регрессии, мобильную производительность и совместимость с существующим интерфейсом. Если я передаю diff, проверяй именно его. Возвращай конкретные замечания: важность, путь и строка, почему это проблема и как исправить. Не заявляй, что запускал проверки, если не запускал. Не предлагай менять несвязанные части проекта. В конце дай короткий вердикт: блокирующие проблемы, неблокирующие улучшения, что нужно перепроверить.
