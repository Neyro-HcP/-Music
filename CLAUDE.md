# Правила работы ИИ с проектом НсП Visual Lab

Перед изменениями прочитай этот файл и `README.md`, затем проверь реальные исходники, которых касается задача.

## Контекст проекта

НсП Visual Lab — браузерная площадка для музыкального визуализатора, 3D-песочницы, инструментов и мини-игр. Основные разделы описаны в `README.md`:

- `index.html` — музыкальный визуализатор.
- `phone.html` — RGB Phone и 3D-физика.
- `tools.html` — инструменты.
- `games.html` — мини-игры.
- `public/` — публичные ресурсы проекта.

Сайт публикуется как статический проект. Не предполагай структуру файлов или технологии, пока не проверишь их в репозитории.

## Общие правила

1. Не переписывай работающие части без необходимости. Делай минимальные изменения строго в рамках задачи.
2. Сохраняй существующий визуальный стиль, навигацию, поведение и совместимость страниц.
3. Пользовательский интерфейс и тексты по умолчанию должны быть на русском языке.
4. Сначала изучай существующие компоненты и CSS; переиспользуй их, а не создавай дубли.
5. Не добавляй библиотеки и внешние сервисы без реальной необходимости. Учитывай мобильные устройства и ограниченные ресурсы браузера.
6. Не отправляй аудио, изображения и пользовательские данные на сторонние серверы без отдельного явного требования.
7. Не добавляй в репозиторий API-ключи, пароли, токены, личные данные или содержимое файлов окружения.
8. Не меняй название проекта, авторство или фирменные элементы без прямого указания владельца.
9. Не утверждай, что проверка прошла, если она фактически не запускалась. Для проверки проекта используй `npm run check`, если команда доступна.
10. Перед крупными изменениями опиши затрагиваемые файлы и возможные побочные эффекты. Не объединяй независимые задачи в один рефакторинг.

## Проверка изменений

После правок:

- проверь синтаксис и связанные импорты;
- выполни `npm run check`, если окружение позволяет;
- проверь затронутые сценарии на мобильной ширине и обычном экране;
- отдельно проверь, что существующие разделы сайта не сломаны;
- перечисли изменённые файлы, проведённые проверки и оставшиеся ограничения.

## Работа с Git

- Не отправляй экспериментальные изменения прямо в `main`.
- Для самостоятельной реализации используй отдельную ветку и Pull Request.
- Не перезаписывай чужие незакоммиченные изменения.
- Не сливай Pull Request без подтверждения владельца проекта.
